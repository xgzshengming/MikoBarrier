## 快速开始

### 用发布版（推荐）

1. 到 [Releases](../../releases) 下载最新一版的 `MikoBarrier.App.exe` 与 `MikoBarrier.Guard.exe`；
2. 两个 exe 放进**同一个目录**（例如 `D:\MikoBarrier\app`），双击 `MikoBarrier.App.exe`；
3. 自包含单文件，**不需要另外安装 .NET 运行时**。

> `MikoBarrier.Guard.exe` 是看门狗，负责自律期间的进程巡逻与 App ↔ Guard 互保，必须和主程序放在一起。

- 温和档 / 狠人档需要管理员权限：在「设置 → 以管理员身份重启」一键提权。
- 数据集中的位置可以改，见下面「数据与日志放在哪」。

### 数据与日志放在哪

程序按这个顺序决定「数据根目录 `Root`」：

1. 环境变量 `MikoBarrier_HOME`（显式指定，优先级最高，测试时也用它做隔离）；
2. `D:\MikoBarrier` / `F:\MikoBarrier` / `E:\MikoBarrier` 中**已经存在**的那个（尽量不占用 C 盘）；
3. 兜底 `%LocalAppData%\MikoBarrier`。

`Root` 下的内容：

| 位置 | 内容 |
| --- | --- |
| `data\config.json` | 密码 / 安全问题哈希、恢复码哈希、名单、主题、策略开关 |
| `data\stats.json` `data\tasks.json` | 统计数据、待办任务 |
| `data\patrol-log.json` | 拦截战报明细 |
| `data\session.lock` `data\shutdown.flag` | 进行中的自律快照、正常关机标记 |
| `data\ui-state.json` | 新手引导是否看过 |
| `data\recovery-code.dat` | DPAPI（CurrentUser）加密的恢复码本机副本 |
| `data\incidents\` | 防绕过事件 |
| `data\runtime\` | App ↔ Guard 互保心跳 |
| `logs\` | `app.log` / `guard.log` |

## v0.2 功能

### 自律
- 预设 5 / 25 / 40 / 60 分钟 + 自定义（1120 分钟）、多轮（112 轮）、中场休息（无 / 5 / 10 分钟）
- 中断欠债：主动退出不计入次数，剩余时间顺延到下一次的第一轮
- 中场休息：自动放开应用屏蔽，但断网档位继续生效（按开始前的设置）

### 任务与时长安排（本次交付）
- **每轮任务**：自律页给每一轮选择 0 / 1 / 多个待办任务；同一任务可跨多轮，同一轮也可关联多个任务。同一轮多任务时，该轮时长与回合按任务数均分。
- **分轮时长**：可以所有轮次使用统一时长（5 / 25 / 40 / 60 / 自定义），也可以勾选「每轮单独设置」逐轮填写 1 - 120 分钟。
- **结束战报**：显示「本次任务：任务A（x 轮 / y 分钟）、任务B（...）」，并把每轮完成的回合 / 秒数自动累计到对应任务。
- **任务清单**：可单条新增，也可按行批量添加；列表支持 Ctrl / Shift 多选后批量删除。
- **自律统计**：统计页按任务展示累计回合与时长；另有本周（周一起）/ 本月汇总，均按本地时间计算。

### 批量操作与交互（本次交付）
- 运行中的程序：按住 Ctrl / Shift 多选后批量加入黑名单 / 白名单。
- 浏览 exe：可以一次多选多个程序；黑 / 白名单列表支持多选批量移除。
- 一行输入框上的鼠标滚轮会转交给页面滚动，不再被输入框吞掉。

### 断网两档（选择时确认："一旦开启，休息时间也会断网！"）
- **温和档**：把网站名单写进 hosts（需要管理员）
- **狠人档**：hosts + 直接禁用网卡（需要管理员）
- 崩溃 / 重启后自动还原网络封锁，不会永久断网

### 密码与找回
- 主密码：16 位，含大小写字母、数字、特殊字符，PBKDF2-SHA512 存储
- **安全问题**：3 个，答案忽略大小写和空格、只存哈希；答对全部 3 题可重设密码
- 设置密码处固定提示：**自律开始后无法更改密码，请开启自律前确保自己记住密码，以防紧急状况下无法退出。**
- **恢复码**：生成后除保存哈希外，还会用 Windows DPAPI（CurrentUser）加密保存到本机 `data\recovery-code.dat`，可在设置页「查看本机恢复码」或退出 / 忘记密码弹窗里查看；换 Windows 用户或换电脑后无法解密，属预期保护。
- **密码提前退出每日冷却**：第 1 次成功后冷却 1 小时；第 2 次成功后冷却 2 小时；冷却结束后可第 3 次；第 3 次后当天直接冻结，次日 00:00 清零。
- **恢复码提前退出**：可绕过密码冷却，但每天只能 1 次（用完后冻结到次日）；使用恢复码重设密码不限次数，且**不会**解除当天密码冷却 / 冻结，防止靠重设绕过。
- 设置页提供「用恢复码重设」「安全问题重设」两条忘记密码路径。

### 名单管理（黑 / 白双向）
- 从运行中的程序添加、浏览 exe、按文件夹添加（适合 Steam / 游戏目录）
- 自身进程不会出现在候选列表里
- 系统核心进程自动放行（explorer、输入法、杀软等）；另有内置组件与系统目录两层保护，详见下方「白名单保护模型」
- **一键白名单**：先预览要加入的程序，再走密码门禁；自动去重，跳过系统核心 / 内置组件 / 系统目录程序。预览窗口按屏幕工作区自适应：列表可滚动、默认只显示程序名，路径可在每行单独展开或一键全部展开，取消 / 继续按钮固定可见，不会被长列表顶出屏幕。
- 网站名单：每行一个域名

#### 白名单保护模型（本次交付）

白名单模式的目标是「只允许工作需要的程序，同时绝不把 Windows 锁死」。放行按以下层次判定：

1. **系统核心进程**（`SystemWhitelist`）：explorer、dwm、svchost、输入法、音频引擎、打印 / COM / 计划任务宿主、Defender 等，黑名单 / 白名单模式都永远放行。
2. **内置必需组件**（`ComponentWhitelist`，仅白名单模式生效）：第三方输入法、显卡 / 音频驱动面板、触控板、杀软（火绒 / 360 / 腾讯 / 卡巴 / Avast / Defender 等），避免误伤；黑名单模式仍可由用户主动屏蔽。
3. **Windows 系统目录**（`SystemAllowPolicy`，仅白名单模式生效）：`System32`、`SysWOW64`、`WinSxS`、`SystemApps`、`DriverStore`、`Windows Defender` 等目录里的程序自动放行；`Windows\Temp`、`WindowsApps` 商店应用、下载目录**不在**保护范围内。
4. **用户白名单规则**：文件 / 文件夹 / 进程名三种规则。
5. **启动链路**：白名单里的程序启动的子 / 孙程序一并放行（最多向上追溯 8 层），适配启动器、WebView2、Java / .NET 运行时宿主、反作弊等多进程结构。explorer / cmd / svchost 等系统进程不会成为链路放行根，避免用命令行绕过白名单。

- **白名单模式只拦截“有窗口”的程序**：服务、驱动、COM 宿主、计划任务、DLL 注入载体等后台进程不会被杀；宿主进程放行后，依附于它的 DLL / COM / 计划任务自然可用。
- **白名单体检**：名单页点「白名单体检」或执行 `--whitelist-audit`，扫描当前机器运行进程，输出分类统计、会被拦截的有窗口程序、必要宿主（explorer / svchost / dllhost / taskhostw / COM / 计划任务宿主）自检；报告写入 `logs\whitelist-audit.txt`。也可以把 `app` 目录整体复制到任意电脑，双击 `whitelist-audit.cmd`（免安装、只读、不写配置，报告在 `audit-home\logs\`），用来在多台「脏」电脑上收集兼容性证据。


### 稳定性
- 异常中断（断电 / 蓝屏 / 无 Kill 事件记录的崩溃）留下快照，下次启动询问"继续还是放弃"；有互保 Kill 事件时自动续跑，不提供放弃入口
- 看门狗 `MikoBarrier.Guard.exe`（进程巡逻 + 守护，黑名单杀 / 白名单模式拦截）
- **App ↔ Guard 双进程互保**：双方每秒写心跳；任何一方被结束 / 失联，另一方会在几秒内记录 Kill 事件并自动拉起。被 Kill 后 App 带 `--killed-restart` 自动续跑，不再给「放弃本次」的绕过选项。
- **Kill 递进欠债**：本自然月第 n 次 Kill 罚 5n 分钟（5、10、15…），当月未偿还余额封顶 60 分钟；封顶后一旦被下一次自律偿还，后续 Kill 会直接补满回 60 分钟；跨月清空 Kill 次数与 Kill 欠债。同一会话 15 秒内的 App+Guard 双杀合并算一次。
- **提前退出欠债**：主动中断时把未完成的专注时长记入下一场第一轮，单次封顶 120 分钟；按自然月自动清空；检测到系统时间回拨时不刷新；旧配置首次登记月份时保留历史欠债，避免升级即清零。
- **启动置前**：主窗口首次显示 / 托盘恢复时一次性请求到最前（SetForegroundWindow + 短暂 Topmost 脉冲后立刻恢复 false），绝不常驻置顶；全屏计时仍保持 `Topmost=False`、不抢焦点。
- 开机自启（可开关）、托盘常驻（可开关）
- **关机 / 注销**：先写入 `shutdown.flag`（Guard 看到后不会把退出当 Kill 去重启主程序）、保存状态、还原网络封锁，然后无条件放行，绝不阻拦 Windows；关机相关异常不弹窗
- 统计：今日完成、累计次数、累计自律时长、历史记录

## 开发与自检

**环境要求**：Windows 10 / 11 + [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)。机器上没有 SDK 时，可以先运行 `tools\install-dotnet.ps1` 装一份便携版（装完会自动把用户环境变量 `MIKOBARRIER_DOTNET` 指向它，不改系统 PATH）。

下面命令都在**仓库根目录**下执行：

```powershell
# 编译（Core / App / Guard / PatrolVictim）
dotnet build .\MikoBarrier.sln -c Release -v minimal

# 核心逻辑回归（基线 185/185）
dotnet run --project .\tools\SmokeTest\SmokeTest.csproj -c Release
# 注意：若检测到已有 MikoBarrier.Guard 在运行，会安全跳过第 10 节端到端巡逻；
#       要跑完整 185/185，请先从托盘退出正在运行的 MikoBarrier。
# 注意：第 9 / 10 节需要靶子进程（已由 sln / SmokeTest 一并编译）；找不到时会明确 SKIP 并给出提示。

# 发布到 .\app\（自包含单文件；该目录已被 .gitignore 排除，分发走 GitHub Releases）
powershell -ExecutionPolicy Bypass -File .\tools\publish.ps1

# 白名单体检（只读、不改配置、不提权）：扫描当前机器，报告写入 logs\whitelist-audit.txt
.\app\MikoBarrier.App.exe --whitelist-audit
# 便携体检：把整个 app 目录复制到目标电脑，双击 whitelist-audit.cmd（只读，报告在 audit-home\logs）

# 界面自检：逐个构造并打开所有窗口 + 新功能探测，结果写入 logs\ui-smoke-test.log
# 当前基线：89 OK / 0 FAIL（必须隔离 MikoBarrier_HOME，避免写入真实 data）
.\app\MikoBarrier.App.exe --ui-smoke-test
# 开发期也可以用源码版（与 app\ 发布版同版本）：
# .\src\MikoBarrier.App\bin\Release\net8.0-windows\MikoBarrier.App.exe --ui-smoke-test --keyboard-test --elevated-attempt

# 可选：注入按键验证 Alt+Tab 被吞 / Win 键放行
.\app\MikoBarrier.App.exe --ui-smoke-test --keyboard-test

# 若 config.json 里 startElevated=true 而当前没有提权，加 --elevated-attempt 跳过自动提权重启
.\app\MikoBarrier.App.exe --ui-smoke-test --elevated-attempt
```

### 本机环境变量（可选，都不改系统 PATH）

| 变量 | 作用 |
| --- | --- |
| `MIKOBARRIER_DOTNET` | 指向 `dotnet.exe` 全路径。SDK 装在非默认位置时，`tools\publish.ps1` 和开发模式的看门狗靠它定位主机。 |

> 杀软误报提示：火绒 / 360 等可能对“批量枚举进程 + 结束进程”的测试程序做启发式误报。SmokeTest 的脏机档案已改为从内置名单动态取样，本机火绒实测不再拦截；若你的杀软仍误报，请把**项目目录**加入信任区，否则编译产物会被隔离。
>
> 「脏机」实测说明：当前开发机是 Windows 10 家庭版，微软 Hyper-V / Windows Sandbox 在家庭版不可用，也没有 VMware / VirtualBox 与离线 Windows 镜像，无法在开发阶段跑真实脏镜像；本轮已用多套合成脏机档案（系统组件 / 输入法 / 杀软 / 显卡 / 后台服务 / 计划任务 / COM 宿主）+ 真机约 250 进程体检覆盖。建议把 `app` 目录复制到真实脏电脑上双击 `whitelist-audit.cmd`（只读、免安装、不写配置），把 `audit-home\logs\whitelist-audit.txt` 发回即可继续扩充组件名单。
