# 发布与分发（维护者手册）

面向仓库维护者：怎么发版本、怎么铺分发渠道、怎么处理签名与误报。

## 一、发一个版本

### 1. 准备

- [ ] `Directory.Build.props` 的 `Version` / `InformationalVersion` 已更新；
- [ ] `CHANGELOG.md` 顶部有对应版本段落（Release 说明会从它自动提取）；
- [ ] 本地跑过核心自检（`tools\SmokeTest`）和界面自检（`--ui-smoke-test`）；
- [ ] 新增素材的授权已记入 `docs\素材许可.md`。

### 2. 打 tag（推荐：CI 自动发布）

```powershell
git tag -a v0.6.0-Miko -m "MikoBarrier 0.6.0-Miko"
git push origin main --tags
```

推 tag 会触发 `.github/workflows/release.yml`：

1. 编译整个解决方案；
2. 跑 185 项核心 SmokeTest；
3. `tools\publish.ps1` 生成自包含单文件；
4. 打包 `MikoBarrier-<版本>-win-x64.zip`、计算 SHA256；
5. 从 `CHANGELOG.md` 提取段落，创建 GitHub Release 并上传
   zip + 两个 exe + `SHA256SUMS.txt`。

也可以在 Actions 页面手动 `workflow_dispatch`，填入已存在的 tag。

### 3. 本地手动发布（可选）

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\publish.ps1
Compress-Archive -Path .\app\* -DestinationPath .\MikoBarrier-0.6.0-Miko-win-x64.zip -Force
Get-FileHash .\MikoBarrier-0.6.0-Miko-win-x64.zip -Algorithm SHA256
```

然后到 GitHub Releases 手动新建，把 zip、两个 exe、`app\SHA256SUMS.txt` 上传。

### 4. 发版后

- [ ] 发布包里的 `whitelist-audit.cmd` 能跑（只读、不写配置）；
- [ ] 更新 winget / scoop 清单（见 `packaging\README.md`）；
- [ ] 到 About 里确认 Release 徽章正常显示。

## 二、GitHub 仓库设置（首次发布后 5 分钟搞定）

### About

- **Description**（带关键词，GitHub 搜索会用到）：

  > Windows 强制自律 / 防摸鱼工具：黑白名单拦截 + 断网 + 键盘封锁 + 双进程互保看门狗。A strict self-discipline & focus blocker for Windows (WPF/.NET 8, open source, no telemetry).


## 三、国内下载与镜像

GitHub Releases 在国内可能很慢，建议准备一个镜像：

1. **Gitee 镜像**：在 Gitee 新建仓库 →「从 GitHub 导入」，同步源码；每个 Release 手动或脚本同步一份 zip；
2. 在 README / Release 说明里写清"国内加速地址"，同时保留 GitHub 为唯一官方来源（避免第三方篡改）；
3. **网盘备份**（可选）：蓝奏云 / 夸克等，注意平台规则与用户观感，且必须同时给出 SHA256；
4. 任何镜像都要标注"与 GitHub Release 的 SHA256 一致"。

## 四、代码签名与杀软误报

- 目前发布版未签名，SmartScreen 会提示"未知发布者"，这是下载转化率的最大损失点；
- 可选方案（按门槛从低到高）：
  - 开源项目免费签名计划（如 SignPath Foundation，需申请并审核项目）；
  - 云签名服务（如 Azure Trusted Signing 一类，有地区 / 资质门槛）；
  - 传统 OV 代码签名证书（约 ¥1000–3000/年，带 USB Key）。
- 签名只解决"发布者身份"，不保证立刻消除 SmartScreen 信誉，仍需积累下载量；
- 被误报时：把安装目录加入信任区是用户的临时办法；维护者可以向火绒 / 360 / 腾讯 / 微软 Defender 提交误报申诉，并在 FAQ 里给出解释；
- **任何时候都不要**让用户关掉杀软安装；公开源码、SHA256、VirusTotal 链接比什么都有效。

## 五、发布说明写什么

Release 说明由 `tools\get-release-notes.ps1` 从 CHANGELOG 生成，另外自动附加下载与校验和。
建议每个版本再补 1–2 张截图或 GIF，尤其是新功能；Release 页面是很多用户第一次真正看到软件的地方。
